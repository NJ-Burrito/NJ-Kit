# Per-item tables: Group A, D, E, F

Open this for the full item-by-item tables (what to look for / how / done looks like) for Group A (A1-A7), Group D (D1-D8), Group E (L1-L10) and Group F (S1-S20). SKILL.md keeps the split/outcome summary and the rules; this file has the row-level detail. Referenced from SKILL.md.

## Group A — machine-checkable, item table

| Item | What to look for | How | Done looks like |
| --- | --- | --- | --- |
| **A1. Policy pages** (1,2,3,5) — privacy, T&C, cookies, refund | One reachable page per named policy, linked, not buried/404/`mailto:`/unopenable PDF. Refund policy is commerce-specific: absent on a brochure site is not a finding, absent on checkout is. | Footer → site map → `site:example.com privacy`; note last-updated date. Tool 18 "Check the fine print" matches `lib/links.js`'s already-fetched link set against expected policy names in English and Arabic («سياسة الخصوصية», «الشروط والأحكام», «سياسة ملفات تعريف الارتباط», «سياسة الاسترجاع»). | 4-row table: policy · found at · status · last updated. DECLARED with URL, or GAP with reason (missing/404/redirects off-site/no date). |
| **A2. Cookie consent timing** (4) | Not *is there a banner* — **was anything stored or read before the visitor agreed** (ePrivacy Art. 5(3)). Reject must be as easy as accept, and must actually stop storing. | DevTools → Application → Storage, clear, reload **without touching the banner**, note first write; then click reject and watch for new writes. Tool 18's `document_start` content script is the only thing early enough to witness the ordering — pairs first-write timestamp against consent timestamp and the cookie jar QA Wrap already reads. | Timeline in ms: page start → first storage write (named, with origin) → banner painted → consent given, plus the reject-path result. GAP if any non-essential write lands before consent. |
| **A3. Form consent** (6) | Any form collecting personal data has a consent control, **unticked by default** (GDPR Art. 7, EDPB consent guidelines). Marketing consent separate from service consent; text links to the policy. | Per form: checkbox present, `checked` on load, `required`, label links to policy, purposes separated. Reachable from `content/recorder.js`'s existing field walk — gains a consent classification, not a new traversal. | One row per form: fields · consent control · default state · linked policy · purposes separated. GAP on any pre-ticked box or uncontrolled personal-data field. |
| **A4. Data minimisation** (7) | Fields the stated purpose does not need (GDPR Art. 5(1)(c), Art. 25 by default). A newsletter asking for a date of birth; a contact form asking for a national ID. | List every field, ask what the purpose does with it. `lib/privacy.js` already holds QA Wrap's own Art. 5(1)(c)/Art. 25 checks — turned outward, it flags high-risk shapes (national ID, DOB, gender, health, biometrics) but cannot know the purpose. | Field inventory with a necessity column, high-risk fields flagged, one named question per unexplained field — partly OBSERVED, partly MANUAL, labelled as both. |
| **A5. Tracking** (8) | Which analytics/ad/fingerprinting endpoints fired, on which load, and whether pre-consent. Cross-reference against the policies. Session recorders get their own line — a screen-replay tool is a different order of collection from a page-view counter. | Network tab, filter third-party, sort by domain. The MAIN-world `fetch`/XHR patch already sees every request — this is a classification pass over data QA Wrap already holds, the cheapest real win on the list. | List of tracking endpoints with first-contact timestamps, each marked named/not named in the policy. GAP on unnamed, separate GAP on anything pre-consent. |
| **A6. Third-party embeds** (9) | Iframes/scripts/fonts/maps/chat/video/payment frames from other origins — each is another company receiving the visitor's IP, and cookie-setters receive more. | Count distinct origins in the Network tab; say the number out loud (*"this page loads from nine other companies"*) — that sentence is what makes a stakeholder act. `lib/origins.js` already carries origins on the timeline; what's missing is the roll-up. | One row per third-party origin: origin · what it serves · sets cookies · named in the policy, plus the one-sentence count. |
| **A7. Business details** (17, presence half) | Registered business name, geographic address, a contact route beyond a form (Directive 2000/31/EC Art. 5). Template placeholder text is the commonest miss. | Footer, contact page, terms, imprint. Watch for literal placeholder strings too: *Your Company*, *123 Main Street*, *info@example.com*, `Lorem ipsum` — a placeholder reads as a real detail, which is worse than an absence. Presence check over A1's fetched set plus a placeholder-string match. | 3 rows — name · address · contact — DECLARED with quoted text + URL, or GAP. Placeholder text is always GAP, never a pass. The truth of these details (are they real) goes to Group C. |

## Group D — site hygiene, item table (D1-D8)

| Item | What to look for | How | Done looks like |
| --- | --- | --- | --- |
| **D1. Horizontal scroll / overflow** (H1, H16, measurable half of H20) | No sideways scroll at any width a visitor uses; no clipped, unreachable content. H1 = symptom at tester's width; H16 = the same fault swept across widths. | `scrollWidth > clientWidth + 1` detects it; walk `getBoundingClientRect().right > innerWidth` to name the culprit (usually one fixed-width image, one unbroken string, one `100vw` inside a padded parent). Repeat at **320/360/390/414** CSS px — 320 is WCAG 1.4.10 *Reflow*'s own width. `content/rtl-stress.js` already runs exactly this two-pass measurement, just wired to RTL stress mode instead of a viewport sweep. | Row per width: scrolls sideways Y/N · overflowing elements by selector · overflow px. GAP at any width that scrolls. Cite WCAG 1.4.10 once, in Group B's row, not here. |
| **D2. Links that go nowhere** (H2, H7, H15) | Three distinct failures a naive link check collapses into one: **Broken** (404/5xx), **Dead** (`href="#"`/`""`/`javascript:void(0)` — no request fires, the classic vibe-coded footer, H7), **Unused** (H15 — works, nothing needs it). | Check footer first (footers outlive the pages they point at), then nav, then body. `content/links.js` already lists `mailto:`/`tel:`/`javascript:` as skipped-not-dropped — the new part is classifying dead-shape hrefs as a finding, not a skip. | Three tables — broken · dead · duplicate — each: link text · href · where · status/reason. "Unused" beyond H15's mechanical tail is MANUAL: a business decision, not a measurement. |
| **D3. Page identity** (H4, H5, H6) — favicon, title, meta description | Favicon present and its href answers 200 (or `/favicon.ico` does) — **a framework default icon (Vite/Next starter marks) is a GAP, not a pass**. Title non-empty, distinct per URL, not a starter string (*React App*, *Create Next App*, *Vite + React*, *Document*, *Untitled*). Meta description present, non-empty, not byte-identical across pages. | View source on `<head>` per page. Reads the same fetched set D2 already walks, plus one extra icon request. | Row per page: URL · title · unique Y/N · meta description present Y/N · favicon status. Label the subsection **"convention, not a standard."** |
| **D4. The 404 page** (H8) | Two required signals: a nonexistent path returns **status 404** (a soft-404 — status 200 for everything — is the worse finding: RFC 9110 §15.5.5, hides broken links from every tool including this one, and is what an SPA fallback route does by default); the body is **the site's own shell**, not a host or framework default screen. | Request something absurd on the site's own origin, read the *status* in the Network tab — the page can say "not found" at status 200. One extra request plus a string check on the body for the site's own header/nav text. | Two rows: status returned · body is own shell. GAP on either. A soft-404 is also flagged as a caveat on D2 — the broken-link count understates. |
| **D5. Image weight** (H10) | Not "are images big" — **is an image far larger than the box it's painted into** (a 3 MB PNG at 400 px is the finding; a 3 MB full-width hero may be fine). | Per `<img>`: `naturalWidth` vs `getBoundingClientRect().width × devicePixelRatio`; ratio above ~2 is wasted bytes. `content/vitals.js` already reads `performance.getEntriesByType('resource')`, rolls up bytes by `initiatorType`, flags responses over 40 KB uncompressed — missing piece is the DOM-side ratio, which turns a byte count into an actionable defect. | Row per oversized image: URL · transfer bytes · natural px · painted px · ratio · format, plus one sentence with total page image weight. |
| **D6. Interactive elements** (H3, H11, H12, H13) — mixed group | Each has a machine half, an accessibility half (Group B), a judgement half (Group C) — **report all three or the row implies a full pass**. Mobile menu (H3): disclosure control at ≤480px; delegate keyboard/name/role (2.1.1, 4.1.2); judgement = right routes. Broken buttons (H11): no listener/form/`type=submit`, `href="#"` only, uncaught console error; delegate a `<div onclick>` with no role/tabindex (axe `button-name`); judgement = works but does the wrong thing. Success messages (H12): anything appear/change after valid submit, live region; delegate is-it-announced (4.1.3); judgement = wording accuracy. Error messages (H13): invalid submit renders a bound error (`aria-invalid`/`aria-describedby`); delegate 3.3.1/3.3.3; judgement = does it help fix the input. | H12/H13 need the form **actually submitted, twice** — the only state-changing step in this whole skill: do it on staging or with the client's explicit agreement, never on a form that files a real request, and say in the report which forms were submitted. `content/recorder.js`'s field walk plus a mutation observation after submit — no axe rule re-implemented. | Row per element/form with **three cells**: OBSERVED (machine half) · delegated (pointer + SC number) · MANUAL (question + owner). Leave MANUAL blank only when genuinely empty. |
| **D7. Placeholder text and copyright year** (H14, H9) | Placeholder (H14): *Lorem ipsum*, *Your Company*, *123 Main Street*, *info@example.com*, *example.com*, *TODO*, *Coming soon*, *Placeholder*, `[Your …]` — in rendered text **and** in `alt`/`title`/`href`, where it survives longest unseen. Same matcher as A7, widened to the whole page. Copyright year (H9): match `©\s*(\d{4})(\s*[–-]\s*(\d{4}))?` in the footer, compare the **last** year to current. | Ctrl-F rendered page for the strings; view source for attribute cases. A text pass over the already-captured DOM sharing A7's string list — usually the fastest finding on the whole audit. | Row per hit: string · where it appears · text or attribute. Placeholder is always GAP, never a pass. Copyright year is one row, OBSERVED vs current year; the *start* year's truth is a business fact → Group C MANUAL, low value. |
| **D8. Clickable logo, phone, email** (H17, H18, H19) | Logo (H17): `header img`/`header svg` has an ancestor `<a>` resolving to same-origin root — a `<div onclick>` fails here *and* in accessibility. Phone (H18)/Email (H19): text matching the pattern **not** inside `a[href^="tel:"]`/`mailto:"`; for links that are, do the digits/address in the href match what's on screen — **the mismatch case is worth the most effort**, since it sends the visitor somewhere unread and is invisible to any check that only asks "is it a link." | Click the logo. Search rendered text for `@` and digit runs, check what each is wrapped in. `content/links.js` already lists `tel:`/`mailto:` as skipped-not-dropped; D8 asks the inverse — which contact details are on the page and *not* in that list. | Row per contact detail: what · visible text · href · match Y/N, plus one row for the logo. GAP on unlinked; GAP, flagged higher, on a mismatch. |

## Group E — policy text, item table (L1-L10)

| # | On screen | Outcome | The signal |
| --- | --- | --- | --- |
| L1 | No Privacy Policy | **machine-checkable** | A1 exactly, already built. No new work. |
| L2 | No "We collect user data" | **mixed** | Keyword pass over the policy's own text for a collection disclosure. Whether the disclosure is *adequate* is a legal reading. |
| L3 | No mention of using AI in PP | **mixed** | Same pass, for automated-processing language. Disclosure duties here are still moving and differ by jurisdiction, so this is presence, never a verdict. |
| L4 | No mention of third party data collectors in PP | **mixed, and the one real GAP** | Keyword pass for named processors, **subtracted from the hosts the session actually saw contacted**. This is the only row on reel 3 that produces a subtraction rather than a presence check, and it is the row worth having. |
| L5 | Not deleting User uploads | **judgement only** | Needs an account, a deletion request and a wait. A test plan, not a page check. |
| L6 | Storage Bucket = Public | **mixed** | Where an asset URL names a bucket host directly, the bucket root may list. Behind a CDN or a signed URL it does not, and the question moves to a console. |
| L7 | Fake testimonials | **judgement only** | Reel 1's point 15, unchanged. |
| L8 | Cancelling longer than sign up | **mixed** | Steps and clicks are countable from a real account. Whether the difference is a dark pattern is a reading of intent. |
| L9 | Auto renew without reminder | **judgement only** | A claim about a billing cycle. Nothing in one session settles it. |
| L10 | AI with no self harm response | **delegate + judgement** | A probe is automatable; designing it responsibly and reading the answer against a safety standard is not this skill's work. **Delegate it the way accessibility is delegated:** run it elsewhere, cite the result, re-implement nothing. |

## Group F — security surface, item table (S1-S20)

| # | On screen | Outcome | The signal |
| --- | --- | --- | --- |
| S1 | hide API keys | **machine-checkable** | Prefix-anchored key shapes in the page source and inline scripts, plus tokens in request query strings. **Prefix-anchored on purpose:** a bare hex string is a cache buster far more often than a secret, and a check that cries wolf on every build hash is switched off within a week. |
| S2 | check env variables | **machine-checkable, opt-in** | Requesting `/.env`, `/.env.local`, `/config.json` unauthenticated. This is a request the site did not invite, so it belongs behind an explicit opt-in scoped to a site the tester owns. |
| S3 | check keys in git | **not the crawler's object** | The repository and its history. Name `gitleaks` or `trufflehog` and move on. |
| S4 | protect admin routes | **machine-checkable, opt-in** | Same shape and the same caveat as S2. |
| S5 | add auth | **mixed** | Does a protected route redirect to a login. Whether the flow itself is sound is deeper testing. |
| S6 | check user perms | **delegate** | Two accounts and a reach across them. Active testing. |
| S7 | sanitize user inputs | **delegate** | Payloads into every input. |
| S8 | protect against XSS | **delegate** | Same tooling as S7. |
| S9 | SQL injection protect | **delegate** | Same again. **S6 to S9 are one delegated step, not four rows pretending to be independent checks.** |
| S10 | check DB rules | **not the crawler's object** | Provider console. |
| S11 | add rate limiting | **mixed, opt-in** | Repeated requests and a watch for a 429. Deciding it is acceptable to do that to someone else's site is the judgement half. |
| S12 | set spend cap | **not the crawler's object** | A billing console. The first sign it is missing is usually the invoice. |
| S13 | secure file uploads | **mixed** | Only where an upload exists, and only with permission. |
| S14 | CSRF protection | **machine-checkable, with a stated limit** | A hidden token field in a posting form. **A missing one is not proof of a hole** — a framework may send a header instead, which a DOM walk cannot see. File it as a question for whoever wrote the form. |
| S15 | check CORS settings | **response header** | Not captured by a session that records requests. Say so; do not infer. |
| S16 | enable HTTPS | **machine-checkable** | The scheme, plus every subresource fetched over plain http. A padlock over mixed content is a padlock doing nothing. |
| S17 | add security headers | **response header** | CSP, X-Content-Type-Options, Referrer-Policy, frame-ancestors, HSTS. The same limit as S15. |
| S18 | secure cookies | **machine-checkable, narrowly** | **Only the unambiguous fault triggers a finding:** no `Secure` on an https page, or no `SameSite` attribute at all. HttpOnly is wrong for a cookie the page's own scripts must read, and `SameSite=None` with `Secure` is a legitimate cross-site cookie. Flagging all three turned a real news front page into "33 of 33", which is a row nobody reads twice. |
| S19 | disable debug mode | **machine-checkable, opt-in** | Force an error and look for a stack trace, a framework debug page or a source map. |
| S20 | check prod settings | **judgement, catch-all** | Reel 2's H20 in a different costume. It re-names S2, S3, S10, S12 and S19 as one umbrella; whatever is left is a person's read of a deployment. **Never ticked.** |
