## 3. `install.py` wired to the applier

New `apply_description_overrides(skills_dir, check_only)`, called immediately
after `install_skills(...)` so the trims land on freshly fetched skills before
`audit_installed` reads them. It shells out to
`scripts/apply-descriptions.py --skills <target>` (plus `--check` under
`--check`) with `PYTHONUTF8=1` in the environment, prints the applier's last two
summary lines, and is **non-fatal by construction**: a missing applier or
overrides file is a `!` and a return, any exception is caught, and a non-zero
return code becomes a `!` rather than a failed install. The rationale is in the
docstring — a description 40 words too long is a token cost, not a broken
install.

`SKILL.md` § "What `install.py` does" gained the step as item 3 (privacy and
MCP renumbered to 4 and 5).
