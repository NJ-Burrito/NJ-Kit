# Lessons — PROJ session 2026-10-12 (Lead)

Each lesson: what happened → the rule that prevents it → where it lives.

## Briefs and rules
1. **Stale rule in a live brief.** Customs switched to staging mid-day; two workers kept stopping at customs ("QA only") because a shared BRIEF.md and a report builder still carried the old rule. → On any rule change the Lead decides the change; a Sonnet worker (a) updates every shared brief in the run folders, and the Lead (b) sends `AMEND:` to every running worker, (c) briefs point to the rule file (`nj-jira/references/<project>.md`) instead of restating rules. → nj-delegate brief clause, nj-qa-pipeline.
2. **Invalid blocked reasons.** Workers marked notes «blocked — الوقت» with 45 min left, and «cannot test — no suite spec». → Valid reasons only: needs a filed request / back-office desk / named missing test data or account / environment down (with the error line). "No ready check" and "time" are never reasons — check by hand. → nj-qa-pipeline verdict rules, BRIEF template.
3. **Lead-imposed clock holds waste time** (an 11:40 sign-in hold idled 3 workers). → Never hold by clock; serialise sign-ins with `portal.lock` + 3-min spacing only.

## Filing quality
4. **Bugs filed without evidence or with a wrong claim** (5031–5033 first went in without screenshots; 5033 claimed both branches, only one was wrong). → Before create: re-verify each branch of the claim yourself, attach masked evidence that SHOWS the defect, and pass the review page (approve) — no evidence, no filing.
5. **False positives from pattern-looking defects** (5039/5041: output «الرقم» ≠ request serial). → Before filing a "mismatch/format" defect, check the same thing on one other service: if every service shows it, it is design → add to the known-not-a-bug list, don't file.
6. **Systemic defect across services** (completion year +1 on 5 services). → One Bug listing every service + request, later services added as a comment — never one Bug per service.
7. **Environment field left empty** read as "QA only". → Always set Environment + env labels (rule in nj-jira §4).
8. **Known not-a-bug list grew today**: «التوقيع الرقمي» (the step itself is never a bug or blocker — inspect the stage and «معاينة المخرج» instead; a reproducible signing failure, 5xx with an error body such as SIGN_HERE not found in PDF, is a process-blocker Bug routed to the operations owner, the owner 2026-10-15; single statement in SKILL.md §3c), output «الرقم» = outgoing letter number, signer directorate taken from the signing staff account's profile (the staging test account), «رخصة المهن» has no «تحقق»/«أتعهد». → nj-jira/references/PROJ.md; check it before every draft.

## Portal / environment facts (PROJ staging)
9. Approved requests show **«عرض المخرج»** in the back-office request view; «معاينة المخرج» exists only at the open signing desk. Look for both.
10. Requests filed by other sessions/accounts are often not viewable («ليس لديك صلاحية» / «تعذر تحميل بيانات الطلب»). → Prefer filing one own request over chasing someone else's.
11. `jira-env.ts` silently overrode the requested env from `jira.config.json` and filed a request on QA by mistake. → Assert the base URL of the run equals the intended env before any filing action; abort otherwise.
12. Payment («الفوترة») only reachable from the office network → record as environment block with the exact error.

## Tooling
13. Jira text search (`summary ~`) rejects Lucene operators (`[ ] ( ) : ·` …) → strip them from the search phrase, then match the summary exactly (fixed in nj_rank.py; same rule for any JQL text search).
14. 7-Zip refuses duplicate basenames (two README.md) → `-spf2` (fixed in nj_rank.py).
15. Unit tests must never open a browser/preview (`NJ_RANK_NO_OPEN`), and portable suites must never hold machine paths (env vars `NJ_RANK_PREVIEW` / `NJ_RANK_SCRIPT`; selftest caught it).
16. A worker wrote a credentials scratch file into the repo root and another used `rm -f` → credentials are read in memory only, never written to disk; deletions only via safe-delete.

## Reporting
17. Report builders copied stale rules into the client report/email. → The report step reads the current rule file and the Lead greps the output for retired rules (e.g. "QA only") before handing it over.
18. Emails are pasted into Outlook → plain text, no markdown bold/tables; Arabic, signed «المالك»; boss has ADHD: 3-line summary, one line per service, «ما يلزم» last.
