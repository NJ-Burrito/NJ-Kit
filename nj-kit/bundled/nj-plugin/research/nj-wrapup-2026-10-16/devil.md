# Devil pass: nj-wrapup (2026-10-16)

PROPOSAL: after testing, one skill files all Jira Bugs/Tasks (parallel Sonnet lanes + Haiku helpers), registers them, logs nj-rank Done Tasks, and writes the boss email + QA message, on the owner's single "file it" request.
ASSUMPTIONS: (A1) the results table is final and correct; (A2) one explicit request is enough consent for irreversible Jira writes; (A3) lanes are independent; (A4) the session is "one notes-ticket, one service"; (A5) counts in the skill/email are derivable by eye.

## Strongest alternative
Make the core short: (1) a `reconcile` script as the checkpoint, (2) auto-file only clean rows, hold risk rows for one AskUserQuestion, (3) email and QA message generated from reconcile data into Desktop files. Lane/Haiku orchestration stays in nj-delegate and is used by size.

## What survives
- The order (classify, file, register, outputs, rank, messages, close) and a checkpoint file per stage.
- The classify table, especially "closed but defect present = new Bug «لم يُصلح رغم إغلاق»", and the six-section untestable Task: L4 read-back matched 6/6.
- Masking, "touch no ticket we did not file", single writers for the tracker, the owner's comments binding, and the pitfalls list (Task has no Environment field, "/" in folder names, nj-rank `service_ar` null).
- Email template shape (verdict, blocker, red before green); only its number sources must become mechanical.

VERDICT: proceed with named changes: (1) reconcile gate and mechanical email counts, (2) risk-flagged rows held for one AskUserQuestion instead of blanket approval, (3) size rule replacing "delegations >= 1", (4) split PROJ profile from generic core, (5) root-cause lane split plus an overlap pass.
