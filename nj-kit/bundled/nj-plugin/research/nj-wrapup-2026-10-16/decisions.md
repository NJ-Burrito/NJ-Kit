## Binding design (build exactly this)

1. **Scripts are the gates (governance N-gov-1, P1/P9/P10/P19):** `scripts/discover.py` (what exists: filed keys by reporter today/session, tracker, nj-rank items today, stored outputs, handoff) · `scripts/reconcile.py` (join results + filed-*.json + GET every key → `trace.md` + `trace.json`; asserts notes = fixed+not-fixed+untestable+blocked+withdrawn with denominators; every key exists with expected type/assignee/labels/links/attachments; exit≠0 blocks everything outward) · `scripts/render.py` (emails AR+EN + QA message + nj-rank titles rendered ONLY from trace.json; lint: no request serials/tokens/internal paths/URLs paths/raw error bodies/test-account names in outward text; AR count == EN count; ≤35 lines per language, first 6 lines carry the message). Stdlib only, `--selftest` in each. Prose rules that are not scripted are labelled HABIT.
2. **Router (P2) + size (P3 as ceilings):** session types: notes-ticket test · QA re-check · multi-service automation run · non-testing work · blocked environment · zero-defect. Table: which steps run/skip. Workers = ceiling from disjoint write-sets: A<6 → Lead, 0 workers; 6–15 → 1 Sonnet filer; ≥16 → ≤ceil(A/4) lanes, max 4, split by root cause/workflow node with a claim table; Haiku helpers only when evidence prep is mechanical and >~10 files. nj-rank ≤3 items → Lead. Receipts state `delegations: n` + why.
3. **Core vs profile (P4):** core has no project commands; `references/profile-PROJ.md` holds note.py, jira:add/track, QA Outputs + Desktop copy, coworker QA rule, Story choice, assignee map (feature dev vs operations owner for integration/infra — N-dev-2), env field quirks.
4. **Gates before classify (P5 + dev 5th gate):** known not-a-bug list → latest dated statement → design lookup (profile hook) → cross-service pattern → test-data/account cause. Fail → not filed, reason recorded.
5. **Risky rows held (P6 resolved):** "upload" files CLEAN rows only. RISKY (Not-Bug precedent with key+reason, client-data dependency, design-inferred only, conflicting tickets, the owner-verdict vs design) are held; asked in ONE AskUserQuestion batch at the END of the run (not mid-run — owner), never shown to the boss as filed/failed (stakeholder); verdict-vs-design conflicts go to the owner only.
6. **Precedence (P7):** the owner's verdict wins until he re-rules; conflict quoted in the held-row question; partial notes split (fixed half listed / not-fixed half filed / untestable half → Task or open item).
7. **Systemic (P8 amended, qa-lead must-not-ship fixed):** merge only same root cause; the Bug lists every affected service with a per-service repro row and a retest checklist covering all of them; later services as comments.
8. **Routes:** P11 blocked-by-data/env → open item with exact error; only reproducible app 5xx + error body = process-blocker Bug (fields: serial type, timestamp, endpoint, status, one-line body); our-tooling blocker → open item. P12 signing wording lives in nj-qa-pipeline §3c (owner) + memory `digital-signature-not-bug.md`; nj-wrapup points to it. P13 untestable → Task ONLY if it names a concrete file/config/BPMN node/variable/template key; else open item; "is blocked by" links. P14 re-check → nj-jira §5 with confirmation + regression before Done; failed → Re Opened same key. P15 only "by design" Not-Bug closures feed the known list, each entry confirmed by the owner (in the end batch).
9. **nj-rank (P16):** code guard in nj_rank.py: `close-mine --apply` skips issues created by a wrap-up (label `untestable`/`wrapup` or keys in the session trace) and refuses when the session trace exists; add `link` helper (Relates via REST). P22: nj-rank's preview-before-file order stays.
10. **Ticket content (P17/P18 + N-dev-1/3 + N-qa-3):** severity AND priority explicit (Medium default, High only true blocker) — table lives in nj-jira bug-template; neutral lineage line «ما زال يظهر — مرتبط بـ <key> (Done بتاريخ …)» in body; sections «أين يُفحص» (where to check), lineage/not-a-duplicate, preconditions, retest block (confirmation steps + regression neighbours).
11. **Email (P19 + stakeholder):** test-summary shape: verdict line, counts with denominators (from trace), blocker, new/existing/untestable, fixed, coverage gaps (blocked+untestable = not covered), residual risk, exit statement naming criteria met/unmet (N-qa-1 exit criteria in trace header), «ما يلزم» last with who/what (no invented dates). AR+EN plain text in chat AND saved as Desktop .txt (owner). Reply opens with a verdict card, then held-row table, then paths (N-owner-2).
12. **QA printouts (N-stake-2):** each file gets print / print-with-known-defect (+key) / do-not-print; only final-stage outputs of requests filed in this session qualify.
13. **Close (P20 amended):** sweep `relay.py sweep --tag`; open staging items table; handoff only at the context threshold or on "end session" (session-handoff owns it); nj-kit sync only if skills changed. Telemetry row + SKIPPED rows instead of retries (N-gov-2).
14. **Removals (P21):** no "delegations ≥ 1", no hard-coded counts anywhere.
